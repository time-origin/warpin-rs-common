# 公共通信协议能力实施方案

- 文档版本：1.1，2026-10-28
- 所属仓库：`warpin-rs-common`
- 已发布基线：全部 15 个 crate 为 `0.2.10`，发布提交 `e23d50e`
- 状态：公共库实现及本机验证完成，发布状态见 [0.2.11 交付记录](../releases/2026-10-28-warpin-rs-common-0.2.11.md)。业务仓实施仍未开始。
- 当前范围：仅公共库。新版现场协议尚未收到，不以旧版基康 UDP 文档作为实现依据。
- 业务仓配套计划：[进出舱传感器接入实施计划](../../../yll-dashboard/docs/进出舱传感器接入实施计划.md)。两仓同级检出时可访问。

## 1. 目标与完成条件

提供可独立使用的 HTTP、TCP、UDP、MQTT、Modbus 通信组件，统一工程约束，但保留各协议的原生语义。公共库不依赖云龙湖实体、数据库表、测点编码、页面、设备型号、报警或控制流程。

完成必须同时满足：公开 API 与错误语义稳定；每个协议有可运行示例；资源有界；任务可停止且失败可观察；成功和失败路径有测试；协议互操作验证完成；统一版本发布后可从 crates.io 单独安装。仅有 trait、配置结构或内存替身不算协议实现完成。

现场设备适配不属于公共库完成条件。模拟服务的协议互操作通过也不等于现场验收通过。

## 2. 现状与复用决策

| 已有能力 | 当前用途 | 本次决定 |
|---|---|---|
| `warpin-http` 的 Axum 服务、响应、探针 | HTTP 服务基础 | 继续复用，不另建统一响应壳和服务启动器 |
| `EndpointClient` / `ResolvedEndpoint` | 模型 POST 调用、参数注入、失败切换 | 保持兼容；新增独立通用客户端，不把工业采集接到该调用链 |
| `warpin-config` | 配置加载与环境识别 | 配置加载保持在应用入口，协议组件接收已校验配置 |
| `warpin-errors` | `ServiceError` | 复用服务错误；补充协议错误分类，不新增平行通用响应模型 |
| `warpin-context` / `warpin-observability` | 请求上下文与 tracing | 复用可用上下文，组件不得初始化全局 subscriber |
| `warpin-event-bus` | Kafka 事件总线 | MQTT 设备会话独立封装，不强行套用 Kafka 提交语义 |
| `warpin-storage` / `warpin-integrity` | 数据访问、规范化与完整性 | 由应用按需使用，通信组件不强制依赖数据库或摘要算法 |
| `warpin-workspace` | 资源分配开发候选 | 与通信无关，不引入通信依赖树 |

## 3. crate 与依赖边界

拟采用以下结构，实施时先核对命名是否已占用：

| crate | 责任 | 明确排除 |
|---|---|---|
| `warpin-http` 新增 `transport` 模块 | 通用 HTTP 客户端与受限响应读取 | 厂商 URL 路径、分页、字段翻译、业务重试 |
| `warpin-transport`（新增） | Tokio TCP/UDP 收发、TCP 分帧扩展点、连接生命周期 | 设备报文解析、业务 ACK、自动协议识别 |
| `warpin-mqtt`（新增） | MQTT 客户端、订阅、发布、确认与会话管理 | Broker 实现、Topic 业务命名、入库与业务去重 |
| `warpin-modbus`（新增） | Modbus TCP/RTU 客户端、标准操作与异常响应 | 厂商寄存器表、PLC 业务联锁、业务轮询调度 |

不建设“万能协议网关”crate，不要求所有协议实现统一消息 trait。HTTP 请求/响应、TCP 字节流、UDP 数据报、MQTT 发布事件和 Modbus 寄存器操作保持不同类型。

TCP 分帧是实际扩展点，可以使用 codec trait；没有多个使用方的配置、缓存和调度能力不提前抽象。跨模块共用的错误分类放入现有错误 crate，不为几个枚举新增基础 crate。

新增依赖统一声明在根 workspace；成员使用 `workspace = true`。所有版本继承根版本。公共库内部可使用 workspace path + version；业务仓只能使用已发布的 crates.io 版本。

候选技术：HTTP 复用 reqwest；TCP/UDP 使用 Tokio；MQTT 评估 rumqttc；Modbus 评估 tokio-modbus 及串口适配。新增依赖前记录版本、维护状态、许可证、Rust edition/MSRV、漏洞扫描和功能重叠，不能直接锁定文档查询当日的 latest。

## 4. 共同契约

### 4.1 配置与认证

必需的地址、超时、容量、最大报文/响应大小在构造时校验，零值、溢出、互斥项或未知枚举明确报错。配置加载仍由 `warpin-config` 完成。公网 HTTPS/MQTT TLS 必须验证证书和主机名；不提供跳过验证的生产便捷开关。

内网明文 HTTP/TCP/MQTT 或 Modbus 必须由调用方显式选择，并记录其安全边界。UDP 来源过滤不是身份认证；需要身份保证时由确定的安全传输/签名方案承担，不能用 IP 白名单冒充认证。

密码、token、私钥和完整连接 URL 的敏感部分不得进入 Debug、Display、日志及错误响应。支持凭据更新时，通过新配置创建并替换连接；本期不承诺透明热更新。

### 4.2 生命周期、背压和取消

- 无后台任务的客户端由调用方持有；需要后台循环的对象返回受监督的任务句柄。
- 提供显式停止和等待结束接口；任务错误及 join error 返回调用方。Drop 只做尽力取消，不宣称清理完成。
- 状态包含 created、connecting、ready、reconnecting、failed、stopping、stopped；仅对应协议需要的状态生效。不得把 socket 已连接等同于设备业务正常。
- 明确最大连接数、待处理请求数、入站/出站队列容量、最大帧长度和每次操作截止时间。
- 队列满时采用明确的背压或拒绝，并返回/记录原因；禁止无界排队或静默丢弃。
- TCP 可以暂停读取施加背压；UDP 无可靠背压，拥塞丢包只能尽力观测，不承诺零丢包。
- 取消可能已发送的请求时，返回“结果未知”而非“未执行”；是否查询实际结果由业务决定。

### 4.3 错误与执行结果

协议内部保存 typed error，至少区分配置错误、连接失败、认证失败、截止超时、协议错误、远端拒绝、资源耗尽、取消和结果未知。记录操作阶段与安全诊断字段；原始底层错误作为内部 source，不直接暴露给前端。

在 `warpin-errors` 中复用/扩展转换，稳定 code 与 msg 的注册表必须随 P1 一起确定并测试。转换不得把远端协议异常、认证失败和未知执行结果全部压成 500；亦不得泄漏厂商原始响应或凭据。`ApiError` 仅用于 HTTP 边界，协议库不依赖 Axum 提取器。

默认不做操作级自动重试。连接恢复和重发分离：只读操作若要重试，必须由调用方显式指定幂等性、次数、退避和总截止时间；写操作默认禁止自动重发。

## 5. 协议专项设计

### 5.1 HTTP：`warpin_http::transport`

计划提供经过构造校验的客户端、请求描述和受限响应读取 API。支持 GET/POST/PUT/PATCH/DELETE 等标准方法、受控 header、bytes/JSON 载荷。响应区分 HTTP 状态与载荷解码错误；不硬编码任何厂商成功码或响应 envelope。

连接、单次读取及整次调用分别有超时。响应按流累计校验字节上限，不能先完整读入再判断；压缩响应若开启，解压后也必须受限。大流量消费者可使用受限流接口，取消读取要释放连接资源。

默认不跟随重定向，不做失败切换。基础地址与相对路径组合不得允许绝对 URL、路径逃逸或跨源携带凭据。请求地址来自受控配置，面向不可信地址输入时必须限制目标网络并覆盖 DNS 重绑定等风险。系统代理是否启用必须显式配置。

服务端继续复用现有 Axum 应用构建能力。HTTP 推送接收的业务 handler 在业务仓；公共库只提供通用 body 限制、超时和认证接入方式。

### 5.2 TCP：`warpin_transport::tcp`

支持客户端连接、服务端监听/接受、受限并发和可选 TLS。默认提供原始字节流；明确 TCP 读取块不是完整业务报文。

内置可验证的定长、长度前缀、分隔符 codec，长度字段位置/大小/字节序、头部计入规则必须显式配置；自定义 codec 接口允许上层解释私有帧。分帧缓存必须有上限，覆盖半包、粘包、超长、残帧和 EOF。无效帧处理策略明确，不猜测或自动切换格式。

连接断开后，未完成写入的交付状态必须明确。禁止自动补发整帧，因为部分字节可能已经到达设备。

### 5.3 UDP：`warpin_transport::udp`

支持 bind、recv_from、send_to、显式来源规则和最大数据报长度。接收缓冲区应足够检测超限数据报，不能把截断的前缀作为完整报文交付；不支持可靠检测的平台必须明确报错/限制支持范围。

返回原始 bytes、来源地址和本机接收时间，不编造设备采样时间。发送成功仅表示交给本机网络栈，不代表远端收到。

公共库不生成基康回执、不解释 dataNumber，也不实现所谓 UDP“恰好一次”。业务确认、重传、补数和去重在设备适配层确定。

### 5.4 MQTT：`warpin_mqtt`

范围为 MQTT 3.1.1/5.0 客户端，版本显式选择，分别验证能力，不自动降版本。提供 TLS、认证、client ID、订阅/退订、发布、保活、遗嘱和版本对应的会话配置；保留 QoS、retain、duplicate 与 packet metadata。

事件循环必须受监督，不能只创建客户端而不驱动事件循环。发布 API 区分进入本地队列、写出、协议确认；QoS 0 不伪造确认。QoS 1/2 的确认也不代表数据库提交或设备执行完成。

入站手动确认必须暴露真实的库/协议能力及会话约束，不能承诺底层未支持的逐消息持久化确认。重连可能引发协议规定的重投递，应用仍需业务幂等；禁止把 QoS 2 宣传为跨数据库的恰好一次。

重连必须有总策略上限、退避与状态事件；会话是否保留、如何恢复订阅和在途消息需要测试。默认不把重启后的本地内存当作持久会话。

### 5.5 Modbus：`warpin_modbus`

首个完整范围为 TCP 和 RTU 客户端；设备侧 server/broker 建设不在本期。标准读写操作覆盖 coils、discrete inputs、holding/input registers 以及标准单写/多写；各操作的功能码、数量上限、异常码和地址校验按标准确定。

使用零基协议地址类型，不把文档中的 40001 等展示地址直接下发。unit ID、串口路径、波特率、数据位、停止位、校验位由调用方显式配置。广播无响应语义不能被误报为成功执行；广播写本期默认拒绝。

提供显式字节/寄存器顺序的通用整数/浮点解码，可处理组合寄存器；不推导设备单位和校准系数。NaN/无穷值是否业务有效由上层决定，不能转成零。

每条 RTU 总线串行调度；TCP 首版也按连接串行操作，避免晚到响应关联错误。请求超时/取消后，连接或总线必须进入可验证的恢复流程，不直接把晚到帧交给下一请求。厂商寄存器布局、轮询组、换算公式、权限和联锁属于业务仓。

## 6. 验证矩阵与发布门槛

| 范围 | 必须验证 |
|---|---|
| 所有组件 | 错误配置、超时、取消、关闭、任务失败、队列满、秘密不泄漏、未知结果语义 |
| HTTP | 正常 bytes/JSON、4xx/5xx、无效 JSON、响应超限、压缩上限、重定向、慢响应、TLS 失败 |
| TCP | 半包/粘包、边界长度、非法长度、慢客户端、EOF、断连中写入、连接上限、TLS、停机 |
| UDP | 完整数据报、空包、超长、来源拒绝、乱序/重复原样交付、停机；明确无法保证的网络丢包 |
| MQTT | 3.1.1/5.0、QoS 0/1/2、订阅拒绝、断线恢复、会话过期、重复投递、手动确认、在途取消 |
| Modbus | 功能码、异常码、边界地址/数量、字序、事务 ID、晚到响应、CRC、RTU 残帧、串口断开、无自动重写 |

单元测试不依赖生产服务和开发机绝对路径。TCP/UDP/HTTP 使用本地临时端口；MQTT 使用隔离 Broker；Modbus TCP 使用测试服务，RTU 使用虚拟串口对及独立硬件互操作记录。TLS 使用测试证书。

为 Linux/macOS 建立明确 CI 支持矩阵；串口实机和 TLS/Broker 等互操作验收记录需独立保存。未执行的环境不能计为通过。示例使用通用 payload，不包含洞号、测点、厂商报文或控制动作。

性能验收必须先记录部署资源与输入模型，再测连接数、报文大小、速率、尾延迟、队列长度、内存上限、丢弃/拒绝计数；至少包含额定负载、超载和慢消费者测试。具体现场 SLA 尚未确定，禁止写入虚构的吞吐承诺。

## 8. 版本与发布操作

`0.2.10` 已发布且不可修改。下一统一版本暂拟 `0.2.11`，真正发版前重新检查远端和 crates.io，若被其他团队占用则重新确定；不得提前让业务仓依赖未发布版本。

新增 crate 与现有 crate 继承根版本；所有内部依赖要求一致。只调整本次必要依赖，记录 lockfile 前后差异。公共库当前忽略 Cargo.lock，本地保留验证用锁文件/摘要与发布证据；业务仓必须提交自己的锁文件。

验证命令（任一步失败均记录并修复，不能把忽略项写成通过）：

```bash
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --all-features --locked -- -D warnings
cargo test --workspace --all-features --locked
cargo build --workspace --all-features --locked
cargo tree -d --locked
cargo audit
```

新协议 feature 组合需分别检查；不能只依赖 all-features。缺少 cargo-audit 时先补齐工具，协议新依赖的安全审查未完成不得声明发布就绪。已有库需要 Bash/GNU 工具的测试应使用记录过的验证环境。

提交前 fetch 并处理其他团队更新，不覆盖未提交工作、不强推 main。基础 crate 先 package/dry-run；依赖新版基础 crate 的后继包，在前置版本注册表可见后验证并发布。发布部分成功后失败时记录逐包结果；不得重发同版本或把部分成功报告为整体完成。

回滚采用消费者锁定上一已验证版本；修复用新版本。只有确认发布存在问题时才评估 yank，不删除源码或伪造版本。

## 9. 本轮不做与待确认

不实现基康协议，不假定 UDP；不实现云龙湖测点 DTO、采样表、告警规则、页面数据绑定、PLC 命令；不升级业务仓依赖。新版现场协议、地址和凭据由现场方提供。

公共库自身仍需在 P0 固化：新增 crate 名称可用性、第三方依赖版本与 MSRV、部署支持矩阵、TLS 策略、测试环境和维护负责人。每个事项未关闭时记录状态和阻塞的工作包，不能用默认值掩盖。

## 11. 实施决策与边界（2026-10-28 更新）

P0–P5 的代码、运行示例、配置与错误路径已经落地；P6 本机回归及依赖安全核对完成，P7 按发布记录执行。具体 API 以各 crate README/Rustdoc 为准，以上“计划”段落保留原设计依据。

- 采用调用方拥有连接、监听器和 MQTT 事件循环的模式，不在库内启动后台任务。状态及错误可由调用方接入 tracing/探针，不初始化全局 subscriber。停止通过 close/abort/drop 显式发生。
- Rust future 被调用者取消时无法再返回 Result；TCP/MQTT 将实例标为不可复用，Modbus 丢弃事务上下文。调用者必须记录自己的取消及可能在途写入，不把取消理解为设备没有执行。
- MQTT 使用官方 native-tls 后端，避免旧 webpki 依赖；HTTP/TCP 使用 rustls >=0.23.46，通用 PEM/身份校验共用。原生 MQTT 事件保留拒绝码/属性，发送端仅开放本期需要的标准操作。
- 完整锁文件 audit 仍有两条未启用可选依赖报告；新增不忽略任何公告的构建范围安全检查。具体处置、证据与维护风险见 [安全记录](../security/2026-10-28-protocol-dependencies.md)。
- 新建 Linux/macOS CI；未在本机执行的 Linux/真实硬件资格不计为通过。现场验收与业务实现仍等待新版资料。
